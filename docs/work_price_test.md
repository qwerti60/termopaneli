# Тестовый прайс работ

Документ описывает тестовый прайс для сметы на работы. Цены примерные, нужны только для разработки интерфейса и проверки расчета. Перед production их нужно заменить реальными ценами и правилами подрядчика.

## Как формировать смету работ

Работы лучше считать отдельным блоком от материалов:

- материалы берутся из каталога товаров и дополнительных элементов;
- работы берутся из прайса услуг;
- каждая работа имеет единицу расчета, цену и правило количества;
- итоговая смета показывает два раздела: `Материалы` и `Работы`;
- при отправке заявки на сервер нужно сохранять оба раздела.

Базовый принцип: пользователь вводит площадь фасада, размеры проемов и дополнительные параметры, а приложение добавляет типовые работы автоматически. Менеджер потом может уточнить состав заявки.

## Правила MVP

Для первого этапа достаточно:

- добавить ручное включение/выключение работ;
- считать монтаж панелей, затирку и подготовку по площади фасада;
- считать доставку и замер как `1` услугу;
- не пытаться точно считать сложные углы и проемы без отдельной формы размеров.

## Что добавлено в данные

Для backend добавлена отдельная таблица `work_prices` в `backend/sql/schema_work_prices.sql`:

- `sku`;
- `name`;
- `description`;
- `unit`;
- `price`;
- `calc_rule`;
- `is_default`;
- `is_active`;
- `sort_order`.

Прайс отдается через `GET /api/v1/work-prices/list.php`.

В `estimate_items` можно хранить работы вместе с материалами через `category = work`, но в приложении разделять их по вкладкам `Материалы` и `Работы`.
