# Проверка каталога в БД (`catalog_materials`, API, приложение)

Пошаговая инструкция для этапа «каталог доп. материалов в БД» и отображения в клиенте. Сводка по продукту и бэклог — в [`estimate_mvp.md`](estimate_mvp.md) (раздел **«Что сделано»** про каталог в БД, **«Что тестировать»**, **«На потом»**). Раздел **9** внизу страницы — экран **Поиск** с теми же API-фильтрами.

## 0. Полный регресс приложения (MVP)

Чеклист по **всему** приложению (гость, сессия, ЛК, смета, сохранение, заявки, админ, PDF, регистрация, не только каталог) — в **[`estimate_mvp.md`](estimate_mvp.md)** → раздел **«Что тестировать»**, якорь **`#mvp-testing-checklist`**: сначала нумерованные блоки, затем **полный перечень** короткими пунктами. **Примерка панелей** (несколько зон маски, снимок в галерею, шаринг) — там же якорь **`#mvp-panel-fit-mask-export`**. **ЛК администратора (заявки, MVP §7)** — **`estimate_mvp.md`** → **`#mvp-admin-lk-stage5`**, **`development_plan.md`** → **`#dev-plan-section-7-admin`**, пошагово **[`testing_admin.md`](testing_admin.md)** (SQL, **`curl`**, Flutter). **Ниже по этой странице** — накат SQL, **`curl`**, картинки и проверки **Каталог** / **Поиск** в связке с API.

**Порядок на стенде (как в `development_plan.md` §1 → §2):** **§1** подготовка → **§2** SQL → **§3** (по желанию) → **§4**–**§6** API и статика → **§7**–**§9** в приложении Flutter; затем полный регресс — **`estimate_mvp.md`** → **`#mvp-testing-checklist`** и пункты **`development_plan.md` §2 Приоритет 1** на том же **`<API>`**. Автоматизация пунктов **§4** (и опционально **§6**): из корня репозитория **`API='https://…/tp_api' bash scripts/smoke_catalog_api.sh`**; для проверки картинки задайте **`STATIC_ORIGIN`** (база сайта, где отдаётся **`/catalog/…`**, без завершающего `/`).

Замените `<API>` на базовый URL API **без** завершающего `/` (тот же смысл, что **`API_BASE_URL`** в приложении: обычно `https://<хост>/tp_api` или аналог, где лежит `public/api`).

## 1. Подготовка

- Убедиться, что с телефона/эмулятора и с машины, где гоняете `curl`, URL API **одинаковый** и открывается в браузере (`<API>/api/v1/catalog/list.php?category=slope`).
- В MySQL — доступ к той же базе, которую использует **`config.php`** бэкенда.

## 2. Накат SQL на сервере

- **Если таблицы ещё не было:** выполнить **весь** файл **`backend/sql/schema_catalog_materials.sql`** (создаст `catalog_materials` с колонкой **`package_qty`** и вставит строки).
- **Если таблица уже была создана старым скриптом без `package_qty`:** один раз выполнить **`backend/sql/migrate_catalog_materials_package_qty.sql`** (идемпотентно: повторный запуск не падает с «Duplicate column»). Затем — как в следующем пункте — блок **`INSERT … ON DUPLICATE KEY UPDATE`** из **`schema_catalog_materials.sql`**, чтобы подтянуть актуальные поля по **`sku`**.
- **Если таблица уже есть и колонка `package_qty` уже есть:** достаточно выполнить из **`schema_catalog_materials.sql`** только блок **`INSERT INTO catalog_materials … ON DUPLICATE KEY UPDATE`** — строки **обновятся по `sku`**, в том числе поля **`price`**, **`package_qty`**, **`is_active`**, **`image_path`** (удобно подтянуть новый состав из репозитория без ручного правления каждой строки).
- После выполнения не должно остаться необработанной ошибки InnoDB о дубликате **`sku`**: при конфликте сработает **`ON DUPLICATE KEY UPDATE`**.

## 3. Контроль в MySQL (по желанию, но наглядно)

```sql
SELECT category, COUNT(*) AS cnt
FROM catalog_materials
WHERE is_active = 1
GROUP BY category
ORDER BY category;

SELECT sku, name, is_active
FROM catalog_materials
WHERE sku = 'SLP-MT-RAL-CUSTOM';
```

Ожидание: для **`SLP-MT-RAL-CUSTOM`** в выборке по **`sku`** поле **`is_active`** равно **0**. В агрегате по категориям учитываются только **`is_active = 1`**, поэтому «RAL под заказ» в счётчиках активных позиций **не** участвует.

## 4. Проверка API (`curl` или браузер)

Все запросы — **GET**, без авторизации. Те же проверки одной командой — см. **`scripts/smoke_catalog_api.sh`** (переменная **`API`**, опционально **`STATIC_ORIGIN`** для **§6**).

1. **Откосы**  
   `curl -sS "<API>/api/v1/catalog/list.php?category=slope&limit=200"`  
   Ожидание: HTTP **200**, тело — JSON с массивом **`items`**; в массиве есть хотя бы один элемент. В нескольких объектах в поле **`name`** (или **`title`**) встречаются подстроки вроде «**250 мм**», «**коричневый 200**» — это признак, что подтянулся расширенный seed из **`docs/catalogs`**. У элементов есть **`sku`**, **`category":"slope"`**.

2. **Редкие категории из seed**  
   По очереди открыть или вызвать `curl`:  
   `…/list.php?category=soffit_lining`  
   `…/list.php?category=front_overhang`  
   `…/list.php?category=consumable`  
   Ожидание: **200**, в **`items`** для **`soffit_lining`** и **`front_overhang`** в эталонном seed по **две** активные позиции; для **`consumable`** — минимум **две** (например монтажная пена и герметик). Если **`items`** пустой — на сервере не выполнен INSERT или таблица пустая / все **`is_active=0`**.

3. **Неактивная позиция не попадает в выдачу**  
   Во **всех** ответах `list.php` для материалов действует фильтр **`is_active = 1`**, поэтому артикул **`SLP-MT-RAL-CUSTOM`** в **`items`** **никогда не должен** встречаться (ни в `category=slope`, ни в `all`).  
   Если установлен **`jq`**:  
   `curl -sS "<API>/api/v1/catalog/list.php?category=slope&limit=500" | jq -r '.items[].sku' | grep -F 'SLP-MT-RAL-CUSTOM'`  
   Ожидание: **пустой вывод**, код выхода **`grep`** — **1** (ничего не найдено).

4. **Панели не сломаны**  
   `…/list.php?category=panel` — как и раньше, отдаются строки из **`thermo_panel_catalog`**; HTTP **200**.

5. **Поле `package_qty` в ответе (п. 5.2)**  
   У элементов с **`"source":"catalog_materials"`** в объекте **`raw`** должен присутствовать ключ **`package_qty`** (значение число или **`null`**). Если в БД колонку ещё не добавляли — ключа не будет, пока не выполнен **`migrate_catalog_materials_package_qty.sql`**. Для smoke после **`UPDATE catalog_materials SET package_qty = 10 WHERE sku = '<из ответа>' LIMIT 1`** повторный **`curl`** должен показать **`"package_qty":10`** (или **10** без кавычек) внутри **`raw`**.

6. **Фильтры `material`, `color` и `thickness` (только `catalog_materials`)**  
   Пример: `…/list.php?category=slope&color=Белый` — в **`items`** только откосы с **`color`** «Белый» (как в БД).  
   `…/list.php?category=slope&material=Пластик&color=Белый` — пересечение условий.  
   Толщина: подставьте значение из карточки (**`thickness_mm`**, а для откосов/отливов/уголков в seed часто размер в **`width_mm`**) — например  
   `…/list.php?category=slope&thickness=250` — в **`items`** только откосы с совпадающей толщиной/шириной по правилам API. Комбинация: `…&material=Пластик&thickness=250`. Некорректный или нечисловой **`thickness`** игнорируется (фильтр по толщине не применяется).  
   Для **`category=panel`** те же query-параметры **не** сужают выборку панелей (см. комментарий в **`list.php`**). В режиме **`category=all`** фильтры действуют только на часть ответа из **`catalog_materials`**; панели в ответе остаются без фильтра по этим полям.

## 6. Картинки по `image_path`

- В JSON возьмите любой **`image_path`**, например `catalog/slopes/slope_plastic_white_250.jpg`.
- Соберите URL так же, как приложение: **`https://<хост>/<путь к корню API>/catalog/slopes/…`** (часто корень сайта = родитель каталога `tp_api`, тогда файл может быть **`https://<хост>/catalog/slopes/…`** — зависит от хостинга).  
- Ожидание: **не** 404 (в репозитории лежат заглушки под пути из seed в **`backend/public/catalog/`**; на проде файлы должны быть залиты туда же или пути в БД поправлены).

## 7. Проверка в приложении Flutter

1. В **`API_BASE_URL`** указан тот же `<API>`, что проверяли `curl` (иначе приложение смотрит «на другой сервер»).
2. Полный перезапуск приложения (**Stop** → **Run**), затем вкладка **«Каталог»**.
3. Горизонтальный список чипов категорий: должны быть пункты **«Подшивка софитов»**, **«Фронтальные свесы»**, **«Расходники»** (если их нет — на устройстве старая сборка клиента).
4. Выберите **«Откосы»**: сетка **не** пустая. Откройте карточку, например «**250 мм**».
5. На карточке: вкладка **«Характеристики»** — строка **«Артикул»** с заполненным SKU; при наличии в ответе API полей **`width_mm`** / **`length_mm`** — строки **«Ширина, мм»** / **«Длина, мм»**. Вкладка **«Описание»** — текст из поля описания материала, **а не** стандартный абзац про «Фасадные термопанели с клинкерной плиткой…» (это важно именно для **`catalog_materials`**, не для панелей).
6. Переключите **«Расходники»** / **«Подшивка софитов»**: сетка не пустая, карточки открываются.
7. Режим **«Все»**: в списке смешиваются панели и материалы (для smoke-достаточно увидеть разные **`category_label`** / типы названий). Учтите ограничение **`limit`** в API: при очень большом каталоге панелей часть материалов в режиме «Все» может не попасть в первую страницу — это известная особенность до доработки пагинации (см. раздел **«На потом»** в [`estimate_mvp.md`](estimate_mvp.md)).
8. **Фильтр** (иконка вверху): выбрать **«Откосы»**, открыть фильтр, задать **цвет** «Белый» и **Применить** — в сетке только белые откосы; при наличии в данных поля толщины — выбрать **«Толщина, мм»** (не «Все»), **Применить**, убедиться, что список сузился; **Сбросить** — снова полный список категории; сменить категорию (чип) — фильтр **остаётся** (те же `material`/`color`/`thickness` уходят в API для новой категории), список перезагружается.

## 8. Типичные проблемы

| Симптом | Что проверить |
| --- | --- |
| В приложении пусто для «Откосы», `curl` даёт пустой **`items`** | Выполнен ли **INSERT**; есть ли строки с **`category='slope'`** и **`is_active=1`** в БД; не падает ли PHP с ошибкой (лог веб-сервера). |
| `curl` работает, в приложении пусто или старый набор | **`API_BASE_URL`** в сборке; не указывает ли на старый бэкенд без наката SQL. |
| Ошибка 500 на `list.php` | Лог PHP; существует ли таблица **`catalog_materials`**; доступ к БД из **`config.php`**. |
| В **`raw`** нет **`package_qty`**, округление по упаковке в смете не срабатывает | Выполнить **`migrate_catalog_materials_package_qty.sql`** (см. **`docs/testing_catalog.md` §2**); перезапросить **`list.php`**. |
| Картинки не грузятся | Фактический URL к **`public/catalog`** на сервере и совпадение с **`image_path`** в JSON. |

## 9. Экран «Поиск» (фильтры API как в каталоге)

1. Открыть **Поиск** в нижней навигации: без текста в поле — подсказка про ввод и про кнопку фильтра; при активном фильтре — дополнительная строка про сужение выборки на API.
2. Нажать иконку **фильтра**, выбрать **материал**, **цвет** и при необходимости **толщину**, **Применить** — в логах прокси или через **`curl`** убедиться, что к **`list.php`** уходят query **`material`** / **`color`** / **`thickness`** (кодировка UTF-8 в URL).
3. Ввести текст поиска (например «откос») — результаты только среди уже отфильтрованного списка.
4. Задать фильтр + запрос, дающий ноль строк — текст **«Ничего не найдено по запросу …»** и предложение сбросить фильтр, если он не «Все».
5. **Сбросить** в шторке — повторная загрузка без **`material`**/**`color`**/**`thickness`** (полный срез **`category=all`**, **`limit=500`** для клиентского поиска).
