# План разработки приложения

## 1. Текущий статус

### Уже сделано

- Регистрация и авторизация пользователя.
- Подтверждение телефона через SMS-код в логике приложения.
- Временный режим без реальной отправки SMS: используется тестовый код `123456`.
- Проверка пользователя в БД после ввода кода:
  - если пользователь есть, выполняется вход;
  - если пользователя нет, открывается регистрация.
- Сохранение токена после успешного входа/регистрации.
- Проверка сохраненного токена при запуске приложения, чтобы не требовать повторную авторизацию.
- Переход на Telegram-канал при регистрации.
- Каталог термопанелей загружается и отображается через API.
- Подготовлены примерные каталоги откосов и дополнительных элементов в `docs/catalogs`; полный стартовый **INSERT** для MySQL — в **`backend/sql/schema_catalog_materials.sql`** (синхронно с `.md` в `docs/catalogs`).
- API каталога подготовлен к выдаче категорий `panel`, `slope`, `corner`, `grout`, `ebb`, `soffit`, `soffit_lining`, `front_overhang`, `plinth`, `fastener`, `consumable`.
- Экран каталога в приложении подготовлен к переключению категорий; сортировка по названию/цене/категории на клиенте.
- В **GET** `catalog/list.php` поддержаны query-параметры **`material`** и **`color`** (фильтр по полям `catalog_materials`); экран **Каталог** передаёт их при применении фильтра; экран **Поиск** — то же при загрузке списка для локального поиска по тексту.
- В **GET** `catalog/list.php` поддержан query-параметр **`thickness`** (числовое совпадение с **`thickness_mm`**, либо с **`width_mm`** для категорий **slope / ebb / corner**, если **`thickness_mm`** в строке NULL — как в текущем seed); экраны **Каталог** и **Поиск** передают его из шторки фильтра вместе с материалом и цветом.
- Экран поиска ищет по названию, описанию, категории, артикулу, материалу и цвету (по загруженному срезу каталога).
- Реализована MVP-смета и **личный кабинет** (хаб «Личный кабинет», сохранённые сметы, мои заявки, Pro по **`is_pro`**, выход с **`POST /api/v1/auth/logout.php`**): см. **`docs/estimate_mvp.md`**, якорь **`#mvp-lk`**. Профиль: **GET/POST** `profile/me.php` и `profile/update.php` (ФИО и email, без смены телефона), заявки, админ-заявки, PDF/share, app-manifest, **гостевой режим** (каталог и смета без входа; вход при сохранении на сервер и заявке по требованиям App Store). Сессия между запусками: **`GET .../auth/session.php`** при старте; при **401** токен очищается; переход на экран входа **не** сбрасывает токен до успешного нового входа.
- В смете для **материалов и работ**: примечание к строке, скидка на строку, **ручная цена за единицу** (`line_unit_price_rub`), ввод количества по нажатию на число; итоги и PDF/текст «Поделиться» учитывают эти поля.
- **Смета п. 5.2 (MVP):** **запас на подрезку** — поле **`cutting_waste_percent`** в **`calculation`** (экран сметы, по умолчанию 5% для новой сметы, 0 при открытии старой без ключа); учёт в **нетто** площади при **«Рассчитать»** для панелей/м² и работ **`facade_area_m2`**. **Округление до упаковки** — **`package_qty`** в **`raw`** позиции (из **`catalog_materials`** после миграции **`migrate_catalog_materials_package_qty.sql`**); **`EstimateService.roundQuantityToPackage`**. См. **`docs/estimate_mvp.md`**, **`#mvp-estimate-5-2-waste`**.
- **Накат каталога на сервер (операции):** пошагово **`docs/testing_catalog.md` §2–§6**; миграция **`backend/sql/migrate_catalog_materials_package_qty.sql`** идемпотентна (без ошибки при повторном запуске).
- **Экран сметы (вкладка «Материалы»):** **`CustomScrollView`** — список позиций и **`_EstimateFooter`** в одной прокрутке (**`SliverList`** + **`SliverToBoxAdapter`**), без **overflow** у блока площади на низком экране; вкладка **«Работы»** — **`Column`** + **`Expanded`** со списком и прокручиваемым подвалом (**`lib/screens/estimate_screen.dart`**, прогресс **2026-05-20**).

## 11. Этап 9. Рекламная сеть

**Частично (MVP):** подключена РСЯ / Yandex Mobile Ads через **`yandex_mobileads`**. SDK инициализируется в **`lib/main.dart`** только на Android/iOS, геолокация для таргетинга отключена. Sticky-баннер **`YandexBannerAd`** добавлен над нижней навигацией на экранах **Каталог** и **Поиск**; при пустом ID или ошибке загрузки баннер скрывается и сценарий не ломается. ID блока приходит с сервера через **`GET .../settings/app-manifest.php`** → **`yandex_banner_ad_unit_id`**; веб-админка сохраняет его в **Прочее → Реклама РСЯ в приложении** (`config.local.php`, текущий блок **`R-M-19410021-1`**). Compile-time параметры остались как fallback / kill switch: **`YANDEX_BANNER_AD_UNIT_ID`** для тестового ID и **`YANDEX_ADS_ENABLED=false`** для полного отключения. Android: **minSdk 23**; iOS: **platform 13.0**.

Пример тестового запуска:

```sh
flutter run \
  --dart-define=YANDEX_ADS_ENABLED=true \
  --dart-define=YANDEX_BANNER_AD_UNIT_ID=demo-banner-yandex
```

Для production ID блока задаётся на сервере через веб-админку; тестовый **`demo-banner-yandex`** нужен только если серверный **`yandex_banner_ad_unit_id`** ещё пустой. Реклама пока не ставится на критические экраны: вход, регистрация, подписка/оплата, персональные данные, отправка заявки, PDF/SmartCalc и админские экраны.
