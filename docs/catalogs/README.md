# Каталоги материалов

В этой папке хранятся подготовительные каталоги для загрузки в БД и последующего вывода через API.

## Файлы

- `slopes_catalog.md` — каталог откосов.
- `additional_elements_catalog.md` — каталог дополнительных элементов: уголки, затирка, отливы, софиты, подшивка софитов, фронтальные свесы, элементы цоколя, крепеж и расходники.

Полный стартовый набор строк для MySQL (повторный запуск обновляет поля по `sku`) лежит в **`../backend/sql/schema_catalog_materials.sql`** — его нужно держать в согласованности с таблицами в этих двух `.md`. Если таблица на сервере создана без колонки **`package_qty`**, перед повторным **INSERT** выполните **`../backend/sql/migrate_catalog_materials_package_qty.sql`**. После наката на сервер см. чеклист **[`../testing_catalog.md`](../testing_catalog.md)**.

## Примерные каталоги для загрузки

Готовые примеры лежат в папке `examples`:

- `examples/slopes_catalog.example.json` — пример API-ответа для откосов.
- `examples/slopes_catalog.example.csv` — табличный пример откосов для ручного заполнения.
- `examples/additional_elements_catalog.example.json` — пример API-ответа для дополнительных элементов.
- `examples/additional_elements_catalog.example.csv` — табличный пример дополнительных элементов для ручного заполнения.

JSON-файлы можно использовать как образец будущего ответа API. CSV-файлы удобно открыть в таблице, заполнить реальные цены и затем использовать для импорта в БД.

## Примерные изображения

Для всех путей `catalog/slopes/*.jpg` и `catalog/elements/*.jpg` добавлены временные изображения в `backend/public/catalog/slopes` и `backend/public/catalog/elements`.

Это не реальные фото товара, а демонстрационные изображения из `placehold.co`, чтобы приложение не показывало пустую заглушку во время разработки. Перед production их нужно заменить на настоящие фотографии материалов.

## Общие правила загрузки

- Артикул должен быть уникальным.
- Цена не может быть отрицательной.
- Позиция без изображения допускается, но приложение должно показывать заглушку.
- Отключенные позиции не должны отображаться в пользовательском каталоге.
- Все цены должны храниться на сервере и приходить в приложение через API.
- При загрузке в БД нужно сохранять категорию, единицу измерения, материал, цвет, размеры и статус активности.

## Рекомендуемые категории API

- `panel` — термопанели.
- `slope` — откосы.
- `corner` — уголки.
- `grout` — затирка.
- `ebb` — отливы.
- `soffit` — софиты.
- `soffit_lining` — подшивка софитов.
- `front_overhang` — фронтальные свесы.
- `plinth` — элементы цоколя.
- `fastener` — крепеж.
- `consumable` — расходники.

## Минимальные поля для БД

| Поле | Описание |
| --- | --- |
| `id` | Внутренний ID записи |
| `sku` | Уникальный артикул |
| `category` | Категория материала |
| `name` | Название |
| `description` | Описание |
| `material` | Материал: пластик, металл, смесь, другое |
| `color` | Цвет |
| `texture` | Фактура, если применимо |
| `thickness_mm` | Толщина в мм, если применимо |
| `width_mm` | Ширина в мм, если применимо |
| `length_mm` | Длина в мм, если применимо |
| `unit` | Единица измерения |
| `price` | Цена |
| `image_path` | Путь к изображению |
| `is_active` | Показывать в каталоге |
| `sort_order` | Порядок сортировки |
