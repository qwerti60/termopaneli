# Смета MVP

## Что реализовано

### Добавление товара в смету

Файл приложения: `lib/screens/product_details_screen.dart`.

В карточке товара добавлены:

- выбор количества;
- кнопка `Добавить в смету`;
- добавление позиции в локальную смету;
- переход на экран сметы после добавления.

Если тот же товар добавляется повторно, количество в смете увеличивается.

### Локальное хранилище сметы

Файл приложения: `lib/services/estimate_service.dart`.

Сейчас смета хранится локально в памяти приложения через `ValueNotifier`. Это MVP-реализация без сохранения на сервер.

Хранится:

- товар;
- количество;
- цена;
- итог по строке.

### Серверное сохранение сметы

Файлы backend:

- `backend/sql/schema_estimates.sql`;
- `backend/public/api/v1/estimates/save.php`;
- `backend/public/api/v1/estimates/list.php`.
- `backend/public/api/v1/estimates/submit.php`.
- `backend/sql/schema_work_prices.sql`;
- `backend/public/api/v1/work-prices/list.php`.

Файл приложения:

- `lib/services/estimate_api_service.dart`.
- `lib/screens/saved_estimates_screen.dart`.

Добавлено:

- таблица `estimates`;
- таблица `estimate_items`;
- API сохранения текущей сметы;
- API списка сохраненных смет пользователя;
- API отправки сохраненной сметы как заявки через смену статуса на `submitted`;
- API тестового прайса работ;
- сохранение сметы по текущему Bearer token;
- загрузка количества сохраненных смет на экране сметы;
- загрузка состава сохраненных смет для просмотра.

### Экран сметы

Файл приложения: `lib/screens/estimate_screen.dart`.

На экране сметы реализовано:

- пустое состояние;
- список материалов;
- изменение количества через `+` и `-`;
- удаление позиции;
- очистка всей сметы;
- итоговая сумма;
- кнопка `Сохранить`, которая отправляет смету на сервер;
- ручной ввод площади в м² для пересчета количества панелей;
- блок с количеством сохраненных смет и последней сохраненной сметой;
- отдельный список сохраненных смет в ЛК;
- открытие сохраненной сметы с просмотром позиций;
- отправка сохраненной сметы как заявки;
- вкладка `Работы` с загрузкой тестового прайса;
- добавление типовых работ по площади;
- ручное добавление отдельных работ.

### Смета на работы

Работы нужно формировать отдельным разделом от материалов. Материалы берутся из товарного каталога, а работы должны браться из отдельного прайса услуг.

Тестовый прайс и правила описаны в `docs/work_price_test.md`.

Рекомендуемая логика:

- вкладка `Материалы` показывает товары и доборные элементы;
- вкладка `Работы` показывает услуги монтажа, доставки, замера и подготовки;
- часть работ добавляется автоматически по введенной площади фасада;
- часть работ пользователь включает вручную;
- в сохраненной смете работы можно хранить как позиции `estimate_items` с `category = work`;
- при отправке заявки на сервер нужно передавать материалы и работы вместе.

## Что сделано в текущем этапе

Добавлена расширенная форма параметров расчета:

- поле `Площадь фасада, м²`;
- поле `Проемы, м²`;
- поле `Периметр проемов, м`;
- поле `Окна, шт`;
- поле `Углы, м`;
- поле `Примыкания, м`.

Подключены дополнительные правила работ:

- `facade_area_m2` считает по чистой площади фасада: площадь фасада минус площадь проемов;
- `opening_perimeter_lm` считает по периметру проемов;
- `window_count` считает по количеству окон;
- `corner_length_lm` считает по длине внешних углов;
- `sealing_length_lm` считает по длине примыканий;
- `fixed_once` добавляет услугу с количеством `1`.

Материалы-панели при нажатии `Рассчитать` пересчитываются по чистой площади фасада, если у позиции есть `area_m2`.

## Что сделано в новом этапе

Добавлен детальный список проемов:

- на вкладке `Работы` появился блок `Окна и двери`;
- можно добавить несколько проемов;
- у каждого проема можно выбрать тип `Окно` или `Дверь`;
- для каждого проема вводятся ширина и высота в метрах;
- приложение автоматически считает суммарную площадь проемов;
- приложение автоматически считает суммарный периметр проемов;
- количество окон считается по проемам с типом `Окно`;
- поля `Проемы, м²`, `Периметр проемов, м` и `Окна, шт` заполняются автоматически, если список проемов не пустой;
- панели и работы по `facade_area_m2` считаются по чистой площади фасада;
- работы по `opening_perimeter_lm` и `window_count` могут считаться от списка проемов без ручного ввода агрегированных значений.

## Что сделано в текущем этапе редактирования

Добавлено сохранение и восстановление параметров расчета:

- в `estimates` добавлено поле `raw_json`;
- `save.php` сохраняет блок `calculation` вместе со сметой;
- `list.php` возвращает `raw_json` сметы и `raw_json` позиций;
- приложение передает площадь фасада, проемы, углы, примыкания и список окон/дверей при сохранении;
- сохраненная смета может быть открыта как текущая редактируемая;
- при редактировании восстанавливаются материалы, работы, площадь, проемы и список окон/дверей;
- в ЛК у сохраненной сметы добавлена кнопка `Редактировать`.

Для работы на сервере нужно повторно выполнить `backend/sql/schema_estimates.sql`, чтобы добавить колонку `estimates.raw_json`, и залить обновленные `save.php`/`list.php`.

## Что сделано в текущем этапе ЛК

Разделены сохраненные сметы и отправленные заявки:

- экран `Профиль -> Сметы` получил переключатель `Сметы / Заявки`;
- во вкладке `Сметы` показываются черновики со статусом не `submitted`;
- во вкладке `Заявки` показываются отправленные сметы со статусом `submitted`;
- у черновиков доступны действия `Открыть`, `Редактировать`, `В заявку`;
- у заявок доступен только просмотр состава;
- пустые состояния показывают разные подсказки для смет и заявок.

## Что сделано в текущем этапе заявки

Детализирована отправка заявки:

- в `backend/sql/schema_estimates.sql` добавлена таблица `estimate_requests`;
- `submit.php` принимает `estimate_id` и `comment`, доступен только авторизованному пользователю;
- `submit.php` берет имя, телефон и email из `user_profiles` текущего пользователя;
- при отправке создается запись в `estimate_requests`;
- повторная отправка той же сметы обновляет существующую заявку, а не создает дубль;
- смета по-прежнему получает статус `submitted`;
- в приложении перед отправкой открывается форма только с комментарием;
- контактные данные сохраняются в заявке из БД, комментарий отправляется из приложения;
- после успешной отправки заявка появляется во вкладке `Заявки`;
- при просмотре заявки показывается комментарий из `estimate_requests`.

## Что сделано в текущем этапе обработки заявок

Добавлен backend-MVP для администратора:

- в `backend/public/config.example.php` добавлен `admin_api_token`;
- `GET /api/v1/admin/requests/list.php` отдает список заявок для администратора;
- список можно фильтровать по статусу `new`, `in_work`, `need_info`, `done`, `closed`, `cancelled`;
- каждая заявка возвращается с контактами, комментарием, данными пользователя, суммой сметы и позициями сметы;
- `POST /api/v1/admin/requests/status.php` меняет статус заявки;
- пользовательский список заявок читает статус из `estimate_requests` и показывает его в ЛК.

Для работы на сервере нужно повторно выполнить `backend/sql/schema_estimates.sql`, чтобы создать `estimate_requests`, залить обновленные PHP-файлы и задать `admin_api_token` в `config.php`.

## Ограничения текущего этапа

- Смета сохраняется на сервер, если пользователь авторизован и сервер обновлен.
- Текущая несохраненная смета после перезапуска приложения очищается, если ее не сохранить.
- Параметры расчета сохраняются в `raw_json`, отдельной нормализованной таблицы проемов пока нет.
- Откосы и отливы пока добавляются как работы/материалы вручную, без отдельной карточки каждого проема.
- Цены `0` показываются как `по запросу`.
- Отдельного веб-сайта админки нет; в приложении есть экран `Профиль -> Заявки (админ)` (токен из `admin_api_token`).

## Что сделано в текущем этапе админ-интерфейса

- экран `Заявки (админ)`: ввод и сохранение admin token на устройстве (`SharedPreferences`);
- список заявок с фильтром по статусу и обновлением;
- карточка заявки: контакты, комментарий, состав сметы, смена статуса через API.

## Следующий этап

Ближайший следующий этап — детализация проемов и доработка сметы:

- отдельно считать откосы и отливы по каждому проему;
- добавить редактирование уже добавленных работ и их параметров;
- нормализовать проемы в отдельную таблицу, если понадобится аналитика и редактирование на backend.

## Что тестировать

- Открыть каталог.
- Открыть карточку товара.
- Изменить количество.
- Нажать `Добавить в смету`.
- Проверить, что открылась смета.
- Проверить количество, цену и итог.
- Увеличить/уменьшить количество в смете.
- Удалить позицию.
- Очистить смету.
- Повторно добавить один и тот же товар и проверить суммирование количества.
- Нажать `Сохранить`.
- Проверить, что после сохранения появился блок сохраненных смет.
- Перезайти на экран сметы и проверить загрузку списка сохраненных смет.
- Нажать на блок сохраненных смет и проверить отдельный список.
- Открыть сохраненную смету и проверить состав позиций, количество и итог.
- Нажать `Отправить как заявку` и проверить, что статус стал `заявка отправлена`.
- Ввести площадь в м² и нажать `Рассчитать`.
- Проверить, что количество панелей пересчиталось по `area_m2`, если это поле есть в данных товара.
- Проверить, что вкладка `Работы` показывает тестовый прайс.
- Ввести площадь фасада на вкладке `Работы`.
- Ввести площадь проемов и нажать `Пересчитать`.
- Проверить, что панели и работы по `facade_area_m2` считаются по чистой площади фасада.
- Добавить окно в блоке `Окна и двери`.
- Ввести ширину и высоту окна.
- Проверить, что площадь проемов, периметр проемов и количество окон заполнились автоматически.
- Добавить дверь и проверить, что количество окон не увеличилось.
- Ввести периметр проемов и добавить работу `Монтаж откосов`.
- Проверить, что количество работы равно периметру проемов с округлением вверх.
- Ввести количество окон и добавить работу `Монтаж отлива`.
- Проверить, что количество работы равно количеству окон.
- Ввести длину углов и добавить работу `Монтаж внешних углов`.
- Ввести длину примыканий и добавить работу `Герметизация примыканий`.
- Нажать `Добавить типовые работы по площади`.
- Проверить, что монтаж панелей, подготовка и затирка считаются по площади фасада.
- Проверить, что доставка и замер добавляются как услуги с количеством `1`.
- Добавить отдельную работу вручную из прайса.
- Сохранить смету с материалами и работами и проверить, что обе группы есть в сохраненной смете.
- Открыть `Профиль -> Сметы`.
- Проверить, что есть переключатель `Сметы / Заявки`.
- Проверить, что черновик отображается во вкладке `Сметы`.
- Нажать `Редактировать` у сохраненной сметы.
- Проверить, что текущая смета открылась с сохраненными материалами и работами.
- Проверить, что площадь, проемы, углы, примыкания и список окон/дверей восстановились.
- Изменить восстановленную смету и сохранить повторно как новую сохраненную смету.
- Отправить черновик как заявку.
- Заполнить комментарий в форме отправки заявки.
- Перейти во вкладку `Заявки` и проверить, что отправленная смета появилась там.
- Открыть заявку и проверить, что комментарий отображается над составом сметы.
- Проверить, что у заявки доступен просмотр, но нет кнопок `Редактировать` и `В заявку`.
- Задать `admin_api_token` в `config.php`.
- Запросить `GET /api/v1/admin/requests/list.php` с Bearer admin token и проверить список заявок.
- Запросить список с фильтром `status=new`.
- Отправить `POST /api/v1/admin/requests/status.php` со статусом `in_work`.
- Обновить вкладку `Заявки` в приложении и проверить, что статус стал `заявка в работе`.
- Открыть `Профиль -> Заявки (админ)`, ввести токен, сохранить, обновить список.
- Открыть заявку в админке, сменить статус и убедиться, что в пользовательском ЛК подпись статуса обновилась.
